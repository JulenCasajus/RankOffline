# RankOffline 0.2.0 — stabilization and release checklist

This document distinguishes the **published 0.2.0-debug.5 baseline** from the **final
debug.6 change batch planned for validation**. Work not yet merged and tested is not
described as released functionality.

## Published debug.5 baseline

- Five downloadable, independently managed official packs: Anime, Manga, Movies, Series, Books.
- Room 14, with explicit migrations preserving stable 0.1.3 personal data.
- Shared normalized `media_*` catalog, search, filtering, pagination, ratings, ranking
  and precomputed group support. No online title discovery.
- Per-pack Show Images, cover management, display settings, and PackId-scoped ratings.
- Offline browsing after installed catalog import; initial Top-100 cover downloads
  can be requested by a pack-specific Show Images preference. User-requested
  Top-N downloads remain available.
- One Downloaded covers count per pack; cover deletion is scoped to that pack.
- Declarative, restricted HTTPS cover references from verified pack metadata.
- Normal catalog updates are non-destructive; explicit **Delete pack and data**
  is destructive for the selected PackId, not other packs.
- Nine supported interface languages and shared palette/theme infrastructure.
- Books: 50,000 Work-level entries with normalized genres and a **very limited**
  initial verified series-group corpus. Do not claim comprehensive Book sagas.

The published debug.5 APK and its five packs/index are a matched set; replacing
any APK or pack asset without rebuilding/verifying matching hashes and source
provenance breaks release reproducibility.

## Final proposed debug.6 changes (not yet shipped)

- Search results display a matching alias as the sole visible primary title, without
  changing the persisted catalog title.
- Welcome vertical layout is about 10% more compact while preserving accessibility.
- Sequential archive transfers with safe overlap of imports for unrelated packs;
  waiting states for pending archive/cover operations.
- Cover network scheduling does not stall for unrelated local imports.
- Merge initially ON when One Cover per Group defaults ON.
- Books initially Show Images OFF; Sticky Score Header ON across all five packs.
- Category picker Download pack action uses theme-correct contrast.
- Preserve same-pack Search/Ranking rows while refreshing filters, sorting,
  typing, Merge and rating results. Keep strict isolation when switching packs.

These changes require focused tests, actual physical-device verification, and
regeneration of any affected manifests, archives and the trusted index.

## Final stable 0.2.0 release gates

1. No data loss on a signed **0.1.3 → 0.2.0** upgrade using the original
   `org.rankoffline.app` application ID and signing identity.
2. Test a separate debug.5 → debug.6 update without clearing app data.
3. Confirm every pack installs, imports, becomes usable, handles optional
   Top-100 image acquisition, and remains usable offline.
4. Verify ratings, notes, profile/category settings, Merge, cover deletion,
   and fast switching across all five packs.
5. Verify every ZIP payload and trusted index SHA-256, the APK-embedded index,
   and manifest-default consistency.
6. The final signed APK, five `.pack` archives and
   `category_pack_index.json` are **seven matching published assets**.
7. Update the current release workflow or carry out a controlled,
   independently verified seven-asset publication: the existing workflow
   creates an APK-only release and is insufficient by itself.
8. Check legal/source attribution, especially AniList provider restrictions
   and third-party artwork redistribution. No unlicensed cover binaries
   are bundled in current official packs.
9. Check `versionName=0.2.0` for the signed release variant, a monotonically
   increasing `versionCode`, no injected secrets, and `git diff --check`.
10. Use a coherent tagged commit; do not replace public assets under a tag
    without documenting the reproducibility consequences.

See [RELEASING.md](RELEASING.md), [PACK_FORMAT.md](PACK_FORMAT.md) and

Room 14 has an exported schema contract. Structural changes require a new
explicit Room version and non-destructive migration, not a same-version repair
or fallback that deletes user data.
