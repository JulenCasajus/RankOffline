# RankOffline 0.2.0 — stabilization and release checklist

**Repository status (2026-10-25):** `v0.2.0-debug.6` is a **published
prerelease**. The related code and further stabilization changes are merged
into `main` through PR #4. The stable `v0.2.0` GitHub Release is **not
yet published**. Passing source checks is not equivalent to validating a
signed in-place upgrade or a public seven-asset release.

## Published debug.6 functionality

- Five independently installable official data-only packs: Anime, Manga,
  Movies, Series and Books, with offline title search, filters, aliases,
  groups, ratings, rankings, and per-pack cover management.
- Room schema version 14 with explicit migration paths for existing stable
  personal data; actual signed `v0.1.3 → v0.2.0` upgrade validation remains
  a separate mandatory release gate.
- Search results show the matching alias as the primary visible title
  without altering the canonical persisted title.
- List contents remain visible when changing search, filters, sorting,
  Merge, or returning from rating within the same pack.
- Welcome layout approximately 10% more compact.
- Sequential archive downloads, safe overlap with unrelated imports,
  serialized Room writes, and explicit pending/queue states.
- Optional initial Top-100 cover download and manual Top-N acquisition;
  cover-download success does not affect pack READY/catalog usability.
- New-install defaults: Books `Show Images` OFF; all five packs
  `Sticky Score Header` ON; Series `Merge` and
  `One Cover per Group` ON. Existing customized settings are preserved
  by conservative preset migration.
- Theme-appropriate contrast in the category chooser, and updated
  default rating profiles and categories for non-Anime packs.
- Nine interface languages. No production catalog is embedded in the Core
  APK; all five packs include zero third-party cover-image binaries.

These features describe the debug.6 prerelease and current merged source;
they are **not** proof that the stable APK or signed upgrade has shipped.

## Additional stabilization merged into main after debug.6

- SQLite WAL explicitly enabled; independent query/transaction executors.
- No global index DROP/CREATE cycle during long pack imports.
- Improved cache handling of cover identities shared across media entries.
- Downloaded-cover counter reflects valid locally available images.
- Automatic cover retry does not expose noisy `Retrying` states.
- More careful handling of HTTP 429 and temporary cover-provider limits.

Reported local checks completed: `testDebugUnitTest`,
`compileDebugKotlin`, `compileDebugAndroidTestKotlin`,
`ReadyPackReadConcurrencyTest`, `CoverManagementIntegrationTest`, and
`git diff --check`. Instrumentation tests were run on a Pixel 10 Pro
emulator, not a physical production device.

## Stable 0.2.0 release gates still to verify

1. Re-run the manual seven-asset release workflow from the **final**
   `main` commit. Confirm it passes all steps and uploads the private
   candidate artifact.
2. Confirm the candidate APK uses `org.rankoffline.app`,
   `versionName=0.2.0`, `versionCode=7`, the original stable signing
   identity, and the production `v0.2.0` pack download URL.
3. Verify exact APK/index byte identity and all pack archive sizes,
   SHA-256 values, manifests, contents, and installed defaults.
4. Confirm a **non-destructive signed** `v0.1.3 → v0.2.0` update on
   an emulator or device with pre-existing real ratings, notes, profiles,
   categories, settings and pack data. Keep a backup and confirm the data
   after upgrading; a debug-to-debug test cannot replace this.
5. Verify five-pack installation, READY, queueing, cover retrieval
   and cancellation as applicable; check usability fully offline.
   Physical-device validation is still desirable.
6. Recheck provider terms, authorization constraints (especially
   AniList), attribution, and prohibition on unlicensed cover-binary
   redistribution. Refer to `DATA_SOURCES.md` and
   `THIRD_PARTY_NOTICES.md`.
7. Merge all release corrections; only after the above gates pass,
   create a single annotated `v0.2.0` tag from the validated `main`
   commit. The tag-triggered workflow must create a **draft**, not a
   public Release.
8. Review the draft's seven matching assets, explicitly publish only
   after sign-off, then confirm a clean online install can fetch all packs
   from the public URL. Do not overwrite previously published assets.

See [RELEASING.md](RELEASING.md), [PACK_FORMAT.md](PACK_FORMAT.md) and
[CATEGORY_PACK_ARCHITECTURE.md](CATEGORY_PACK_ARCHITECTURE.md).

Room 14 has an exported schema contract. Structural changes require a
new explicit Room version and non-destructive migration, not a
same-version repair or fallback that deletes user data.

## After 0.2.0

## Historical emulator measurements (not release guarantees)

These were measured on a Pixel 10 Pro emulator with local packs staged into private storage (no real network download). Times vary with hardware/storage.

| Pack | First import to READY, earlier | Later optimized |
|---|---:|---:|
| Anime | 81.9 s | **67.5 s** |
| Manga | 35.0 s | **29.7 s** |
| Series | 130.6 s | **120.3 s** |
| Movies | 136.4 s | **115.4 s** |
| Books | 122.8 s | **106.3 s** |

Follow-up logs showed generic catalog auxiliary genres/credits/alias inserts dominated the import time. Startup after import reused unchanged catalog/group metadata, although scanning/recovering all five packs still took time in that emulator.

Observed Merge SQL pages: ~0.31 s for 200 Series entries at offset 300 and ~0.18 s for Movies (earlier test); rated-group ranking sampled ~96 ms before / ~69 ms after for 58 candidates. These are isolated benchmark runs, not device-wide guarantees.
